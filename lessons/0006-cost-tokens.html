第 6 课 · 模块 M2 · 工程地基 · 收官

越聊越贵：把每次调用算成账
（成本与 token）

前五课你一直在"调模型"，却从没问过一句：这一轮对话到底花了多少钱？今天把 Agent 的账本翻开——读 usage、分开 input/output 计价、用 max_tokens 封顶最坏账单、把每轮不变的前缀交给缓存。你会亲手量出那句面试必问的答案：为什么 Agent 越聊越贵？

使命：3 个月转 AI 应用工程师 约 60–80 分钟 需要：第 5 课跑通的环境（venv + 环境变量） 花费：几分钱 token

面试官考工程化，有句几乎必问的开场："你的 Agent 上线后，每个用户一聊就是几十轮，一个月下来烧多少钱？你凭什么保证不破产？" 新手答"我用的模型很便宜"；老手会先纠正提问里的一个错觉——Agent 烧钱的大头常常不是"模型贵"，而是"越聊越贵"： 模型是无状态函数，它不记得上一个请求，所以你每一轮都得把全部历史 + system + 工具说明书重新发一遍。 对话越长，每一轮要付的 input 就越多。本课的实验，就是把这条曲线亲手量出来。

1 · 心智模型：一次调用是一笔"拆得开"的账

账单的最小单位：input + output，分开计价

你每发一次 API 请求，返回的 response.usage 就是你这一笔的明细。它至少告诉你两个数： 

usage.input_tokens    # 输入 token 数：system + 工具说明书 + 你发的整段 messages
usage.output_tokens   # 输出 token 数：模型吐出来的（含 thinking、含正文）
（缓存命中时还会有 cache_read_input_tokens / cache_creation_input_tokens，见第 4 条）

定价是按 token 数 × 单价，而且 input 和 output 分开计价，output 通常比 input 贵很多。 拿你实际付费的 DeepSeek v4-flash 低谷价（2026-08-17 峰谷定价后，周日全天低谷）举例： 

                 输入(缓存未命中)   输入(缓存命中)    输出
deepseek-v4-flash   ¥1.5 /百万       ¥0.05 /百万     ¥4.5 /百万   ← 输出是输入的 3 倍
deepseek-v4-pro     ¥4.5 /百万       ¥0.15 /百万     ¥13.5 /百万  ← 更强模型更贵，但"结构"一样

价格会变、按官方当日为准；这里只练"怎么算"。记住结构规律就够面试用：输出比输入贵、缓存命中比未命中便宜、强模型比弱模型贵——每一家都长这样。

最大的坑：每一轮，模型都把整段历史从头重读一遍

单轮问答很便宜，因为输入就是"一条问题 + 一点上下文"。可你的 Agent 是循环：每一轮都要把 messages 里从第一条到最新一条的全部内容重新发给模型。模型没有任何记忆捷径—— 它每次都是"白纸一张 + 你把整份档案拍在它面前"。 

第 1 轮模型调用：读  [system+工具] + [问题1]                          ≈ 445 tokens
第 1 轮模型再调：读  [全部上面] + [你调 get_weather 的记录+结果]         ≈ 526 tokens   ← 连工具往返都重读
第 2 问模型调用：读  [第 1 问全部] + [问题2]                            ≈ 553 tokens
第 3 问模型调用：读  [第 1、2 问全部] + [问题3]                         ≈ 667 tokens
（数字是本课镜 2 的一次真实运行——完整历史 445 → 553 → 667，每问 +100 左右，只涨不跌）

于是"越聊越贵"不是比喻，是无状态函数的宿命：对话越长，每一轮模型要读的东西越多。 第 3 问那一轮，模型读的是 前两问的全部内容，而不是"第 3 问"这一句。

一句话记忆

模型不记得你，所以你每轮都要把整段历史重讲一遍——这就是 Agent 独有的成本曲线。 同样是烧钱，单轮问答是"按次算"，Agent 是"按对话长度 × 轮次"算：聊得越长，每一轮都越贵。

两个"防误读"：max_tokens 与缓存，都别当万能药

有人一听成本就去调 max_tokens。它是单次输出账单的天花板（最坏烧多少 output 的封顶）， 但有两件事它管不着：① input 那一头照旧全算（历史重读一分不少）；② thinking 与正文共享这个预算—— 第 3/5 课埋过：预算给太小，thinking 先吃光，你为那些输出 token 付了钱，却一个字都没见到（镜 3 实锤：max_tokens=32 时可见正文是 0 个字）。

缓存呢？它确实能把成本砍一大截——原理是：把每轮都不变的前缀（system + 工具说明书 + 长指令）存起来， 下一轮命中了就按超便宜的"缓存命中价"算，而不是全价。但请看清它砍的是哪一段： 缓存砍的是"重复读的单价"，砍不掉"每一轮都在读一遍"这件事本身——新增的对话（缓存未命中部分）永远全价。

本课一句话核心（请记到能默写）

Agent 烧钱 = 输出单价高 + 每一轮重读全部历史。 把一次调用拆成 input / output 分开计价，用 max_tokens 封顶最坏输出，让每轮不变的前缀命中缓存降低重复读的单价—— 再把每一轮读 usage 记账，你才算真的"把 Agent 算成账"。面试答成本，先答"多轮重读历史"这一层，再答缓存，就比只背价格表高一档。

诚实提醒（教师实测，必读）：本课数字是"量级感"，不是报价

① 价格以官方当日为准：本课全部金额用 deepseek-v4-flash 低谷价（今天周日）练公式；DeepSeek 2026-08 刚峰谷调价且还在变动，别把本课金额当合同。 ② 自动缓存命中是"尽力而为"：同一前缀第一次出现时 cache_read 为 0（还没跑热），第二次起才可能命中。别把某一次 cache_read=0 当成"这个端点不支持缓存"。 ③ 镜 2 / 镜 4 的 token 数与金额是一次真实运行的抽样，模型每次回答略不同，数字会小幅波动——看"趋势与量级"，别抠个位数。 ④ 想彻底严谨，官方计数请查原典里 Anthropic 的 Token counting 文档（本课只用 usage 与 count_tokens 两样官方接口量"真实读了多少"）。

四镜各盯一个东西：

# 镜 1 · 读 usage：一次调用的账单长什么样
写一首诗（短输入长输出）→ in 和 out 谁大？带 system+工具的一次请求 → input 里装了多少东西？
        盯：usage 有几个字段？cache_read 这次亮了没？（冷启动常是 0，跑热才亮——别当端点不支持）

# 镜 2 · ★ 越聊越贵：同一 agent 连答 3 问，完整历史一路涨（本课 decisive）
完整 prompt 由 count_tokens 实测：445 → 553 → 667 只涨不跌；每轮模型调用都 ≈ 此刻完整历史。
        盯：cache_read 是不是越滚越大（自动缓存吃掉重复前缀）？usage.in（新增）是不是一直很小？
        结论：缓存把重复读打折了，但"每轮都在读越来越长的历史"这件事，任何端点都省不掉。

# 镜 3 · max_tokens：单次输出账单的"封顶"，不是省钱工具
同一句写散文，max_tokens=32 vs 2048 → 32 那笔 stop=max_tokens、可见正文常常 0 个字（thinking 吃光预算）
        盯：你为 32 个输出 token 付了钱却 0 字可见；2048 那笔才 end_turn、357 字。封顶 ≠ 省钱。

# 镜 4 · 成本换算：把真实 token 套价格，估一个月烧多少
同一场 3 问对话：完全不缓存 ≈ 0.66 分，DeepSeek 自动缓存后 ≈ 0.22 分（省约 2/3）。
放大到 100 用户 × 30 问/天 × 30 天：不缓存 ≈ 199 元/月，自动缓存 ≈ 66 元/月 —— 量级感，非报价。
陷阱①：只盯 usage.input_tokens 单独一个数

在会做自动前缀缓存的端点（DeepSeek 系），input_tokens 报的是未命中缓存、按全价算的那部分； 命中缓存的重复前缀记在 cache_read_input_tokens。只看 input_tokens 会让你误以为"每轮没重读历史"， 得出"越聊并不越贵"的错误结论。要看"模型这轮到底读了多少"，把两项加起来（或直接用 count_tokens(messages) 量完整 prompt）。

陷阱②：以为 max_tokens 调小就是在省钱

镜 3 是反例：调太小，thinking 先吃光预算，你为看不见的字付了钱还得到一次截断（stop_reason=max_tokens， 记得第 3/5 课的收尾检查）。max_tokens 的正确定位是"给最坏一笔输出封顶"，不是"日常省钱的旋钮"； 真正的 input 大头（历史重读）它一分都管不着。

陷阱③：把"缓存省了 2/3"当成"成本不会再涨"

镜 4 里缓存让一场对话从 0.66 分变 0.22 分——但这是打了折扣的单价，不是停止的增长。 对话越长，新增（未命中、全价）的部分越多。想压"越聊越贵"的斜率，缓存帮不上，得靠第 4 把扳手： 别让对话无限长（长对话截断 / 摘要历史）。
