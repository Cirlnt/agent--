第 1 课 · 模块 M1 · 核心心智模型

Agent 的最小闭环：
一次对话是怎么变成"智能体"的

看懂这一个循环，你就看懂了 90% 的 Agent 框架。今天你会亲手跑起来一个会"自己决定调工具"的小程序。

使命：3 个月转 AI 应用工程师 约 45–60 分钟 需要：一个 API key + Python 3.13（你已有） 花费：约几毛钱人民币的 token

AI 应用工程师面试几乎必问一个题："什么是 Agent？它和一次 API 调用有什么区别？" 多数人答不上来，是因为他们只见过框架（LangGraph、OpenAI Agents SDK…）怎么"调用 Agent.run()"， 却从没见过这个函数内部真正在跑什么。今天我们把那层壳剥掉。

1 · 心智模型：先看穿"调用"与"循环"

一次大模型调用，本质是个无状态函数

你给 client.messages.create(...) 一段话（角色是 user），它返回一段话。 它没有记忆、没有主动性、不能动手——它只是一个"文本进、文本出"的函数。 LLM call 本身不会帮你订票、不会查数据库、不会写文件。

那 Agent 凭什么"能办事"？拆开看，它只比你平时多出 三样东西：

  • 工具（Tools）——你声明的"它可以调用的函数清单"，真正执行的是你的代码；
  • 可续的历史——每轮把对话原样积累下去，模型因此"记得"之前发生了什么；
  • 循环（Loop）——上面两者拼起来，反复"发请求→执行工具→喂回结果"，直到模型给出最终答案。

Anthropic 官方对 Agent 的定义，一句话就能讲透——它其实就是"一个在循环里用工具干活的大模型" （原文："an agent is an LLM that is using tools to perform a task in a loop"）。 — Anthropic, Building Effective Agents (2024)

Agentic loop：那 4 步的机器

把这个循环画出来，是这一整课唯一必须记住的东西：

  你的程序(你的代码)                      大模型 API
  ① 发消息(含历史+工具清单) ────────────►  读题、思考
                                              │ 想要更多信息？
                                              │ (例如"巴黎天气是多少？")
  ② 收到 tool_use（含参数） ◄────────────  │
     ↓
  ③ 你执行 get_weather("巴黎")，拿到结果
     │
  ④ 把 tool_result 喂回去 ──────────────►  继续思考…
                                              │ 足够回答了吗？
  ②' 收到 tool_use ◄────────────────────    │  是 → 返回纯文本
     ↓ (再执行、再喂，可反复)
  ⑤ 直到返回 end_turn（纯文字答案）◄───────  这就是最终回答
一句话记忆

循环条件：模型返回 tool_use → 你执行工具 → 把结果喂回去 → 再来一轮。
退出条件：模型返回 end_turn（纯文字答案）→ 停止，输出给用户。

这四步有一个你以后会反复听到的名字：ReAct （Reason→Act→Observation，推理、行动、观察）。Agentic loop 就是 ReAct 的工程实现—— 面试时能主动说出这层关系，很加分。

反直觉提醒：不是越"自由"越好

Anthropic 反复强调一个面试也爱考的观点：先分清楚你要的是 Workflow 还是 Agent。 Workflow = 路径由代码写死、LLM 只填空（更可控、更便宜、更好调试）； Agent = 路径由模型自己定（更灵活，但更贵、更慢、更难预测）。 "能用简单方案解决就别上 Agent" 是他们的第一条建议——因为复杂度的代价是实打实的：多次调用叠延迟、token 翻倍、bug 更难查。 今天先记住这个判断，第 2 课起我们再逐个看它的模式。 — 同上，Anthropic

第 2 步 · 运行最小 Agent（我已经帮你写好，文件在工作区）

完整代码在 D:\agent学习\code\0001-minimal-agent.py。你也可以对照下面自己敲一遍——自己敲一遍记得更牢。

# minimal_agent.py — 最小的"智能体"：一个会查天气的循环
# （你的环境 = DeepSeek Anthropic 兼容端点，代码与真 Anthropic 一致）
import sys
sys.stdout.reconfigure(encoding="utf-8", errors="replace")   # Windows 防乱码
import anthropic

MODEL = "deepseek-v4-flash"   # 想更强换成 "deepseek-v4-pro[1M]"

client = anthropic.Anthropic()   # 自动读 ANTHROPIC_BASE_URL + ANTHROPIC_AUTH_TOKEN

# --- 1) 工具的真实执行代码：在你这里，不在模型那里 ---
def get_weather(city: str) -> str:
    """查询某城市当前天气（教学用假数据，真实场景换成调天气 API）"""
    table = {"北京": "晴，18°C", "上海": "多云，23°C",
             "巴黎": "雨，14°C",  "纽约": "晴，26°C"}
    return table.get(city, f"暂无 {city} 的天气数据")

# --- 2) 把工具"说明书"给模型看：名字/说明/参数结构 ---
TOOLS = [{
    "name": "get_weather",
    "description": "查询某个城市的当前天气。当用户问天气时使用。",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string",
                              "description": "城市名，如：北京"}},
        "required": ["city"],
    },
}]
EXEC = {"get_weather": get_weather}   # 名字 → 真实函数

# --- 3) 对话历史从这里开始 ---
messages = [{"role": "user", "content": "帮我查一下巴黎现在的天气怎么样？"}]

# --- 4) ★ agentic loop：循环到模型给出最终文字答案为止 ---
while True:
    response = client.messages.create(
        model=MODEL, max_tokens=4096, tools=TOOLS, messages=messages,
    )

    # 情况一：模型想调工具 → 执行它，把结果喂回去，继续循环
    if response.stop_reason == "tool_use":
        messages.append({"role": "assistant", "content": response.content})
        results = []
        for block in response.content:
            if block.type == "tool_use":
                print(f"✳ 模型想调用: {block.name}({block.input})")
                output = EXEC[block.name](**block.input)   # ← 真正执行的是你
                results.append({"type": "tool_result",
                                "tool_use_id": block.id,   # id 必须对上
                                "content": output})
        messages.append({"role": "user", "content": results})
        continue

    # 情况二：模型给最终文字答案 → 输出并结束
    if response.stop_reason == "end_turn":
        final = next(b.text for b in response.content if b.type == "text")
        print("✓ 最终答案：", final)
        break

    # 其它停止原因（截断/拒答等）——后续课程专门处理
    print(f"! 意外停止：{response.stop_reason}")
    break

运行：python minimal_agent.py。你应当看到类似输出：

[工具请求] 模型想调用: get_weather({'city': '巴黎'})
最终答案：巴黎现在在下雨，气温大约 14°C，出门记得带伞。

恭喜——你刚刚目睹了 Agent 的全部秘密：模型并没有"联网查天气"，它是"想用工具"→ 你执行 → 它读结果 → 组织成一句话。它甚至不知道工具背后是假数据还是真 API——这层"不知道"正是 Agent 架构自由度的来源。

第 3 步 · 两道挑战（做第 1 道就算本课完成）

挑战 A（必做，2 分钟）：把用户问题改成 "你好！"，再跑一次。观察它没有调用任何工具、直接 end_turn 返回——这证明"调不调工具"是模型根据语境自己决定的，而不是脚本写死。

挑战 B（加分，10 分钟）：给它加第二个工具 get_current_time（返回 datetime.now() 的实时时间，不需要参数，input_schema 用 {"type":"object","properties":{}}）。然后问："现在北京时间几点？巴黎天气如何？" 观察它并行调用两个工具——因为我们的循环遍历了 response.content 里的所有 tool_use 块。
