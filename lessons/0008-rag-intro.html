RAG 上手：把"最相关几段"喂进上下文
（检索注入 · embeddings · 向量检索）

第 7 课把话说死了：想让 Agent "记得久 + 不无限烧 + 细节不丢"，窗口/摘要都做不到，出路是——把资料存到外面，每轮只把最相关的几段检索进来喂。今天就用一套真能跑、零花费的最小 RAG 把这句话变成代码：切块、embedding、向量检索、top-k 注入。顺便点破一个幻觉：模型能答它没背过的公司政策，不是它记住了，是你在开考前先帮它翻了书。

使命：3 个月转 AI 应用工程师 约 90–120 分钟 需要：第 7 课环境 + 本课自带的本地 bge 模型（免下载、免联网） 花费：¥0 向量 + 几分钱 token

面试官爱问一句："你们公司有个新政策，上线当天就有人来问——模型没训练过，怎么答得上来？" 新手会说"那就把文档喂给模型 / 换个更强的模型"。老手会纠正方向：不是训练、也不是换模型——是 RAG： 在回答之前，先从资料库里把"答案所在的那几段"检索出来，塞进这一次的上下文，让模型开卷作答。 上一课你已经为这句话的"为什么"铺了路；本课把"怎么做"做出来，并亲手量它到底值在哪。

1 · 心智模型：RAG 是"先翻书、再答卷"的两段式

拆两半，别神化：先检索，再增强生成

RAG = Retrieval-Augmented Generation，翻译过来就是检索增强生成，两个半场：

  • 检索（retrieval）：模型没见过你的资料 → 由你（应用层）先到资料库里，把和当前问题最相关的几段原文找出来。第 7 课里那层"外部记忆"就从这里被捞回来。
  • 增强生成（augmented generation）：把这「几段原文 + 问题」一起发给模型。模型还是那个无状态函数（第 6/7 课立的），它做的事没变——变的只是这次请求里多了几段精选原文。
一句话定义（面试先答这句）

RAG = 先把资料切成块、算好向量；提问时把问题也变向量，挑出最接近的几块原文塞进 prompt，再让模型只依据这些原文作答。 模型没换、也没背你的资料；RAG 改的是"这次喂了什么"。

一套最小 RAG 就五步（手写给你看）

① 切块 chunking     手册 → 切成 8 个主题自洽的段落（每块是一个独立小主题，含具体规则/数字）
② 每块算向量 embed   每个块过一遍 embedding 模型 → 变成一个 512 维数字向量
③ 建索引 index       8 个 (文本, 向量) 存成一张表  ← 这就是"向量库"的全部真身
④ 检索 retrieval     用户提问 → 问题也变向量 → 和 8 个向量比相似度 → 取最像的 top-k 块（k=3）
⑤ 注入 augmented     把这 top-k 块的【原文】拼进 prompt：参考资料 + 问题 → 模型只依据资料作答

第①步决定"检索的粒度"，第④步的 k 决定"喂多少"——这两处是后面要亲手调的两颗旋钮。 全流程里，真正"聪明"的只有第②④步里的 embedding 和相似度；其余都是搬砖。

embedding：把"语义"翻译成"几何"

检索凭什么知道哪段相关？关键词不够——同事问"出差报销多少一晚"和你手册里写的"出差住宿报销：一线每晚上限 600 元"， 一个字都对不上。所以要用语义检索：embedding 模型把一段文字映射成一个向量（一串数字，本课 512 维）。 语义越接近的两段文字，它们的向量在空间里就离得越近。于是"找最相关"变成"找向量最近邻"，比较的距离叫余弦相似度（cosine，越接近 1 越像）。

铁律：向量只在自己这个 embedding 模型里可比

别拿两家 embedding 模型算出的向量互比相似度——每个模型有自己的一套"坐标系"， 拿 bge 的向量跟 OpenAI text-embedding-3 的向量算余弦，就像拿公里数比斤两。凡是跟你强调"embedding 可比"的，先说清是在同一个模型内。

还有一个新手必混的点：embedding 模型不是对话模型——它输出的是数字向量，不是文字。 所以做 RAG 天然是"两家组装"：对话走 DeepSeek/Claude，向量走另一个来源。 顺便交个底：DeepSeek 官方 API 至今没有 embeddings 端点（2026 实测，404）；Anthropic 官方也不提供向量化（官方最佳实践用 Voyage 等伙伴模型）。 本课向量来源 = 本地 bge 小模型（BAAI/bge-small-zh-v1.5，ONNX CPU 跑）→ 零账号、零费用、断网可重跑。你后面在生产里会换成云端的 embed 服务，接口概念完全一样。

"向量库"不神秘：一张表 + 排序

你可能听过 Chroma / FAISS / pgvector……它们叫"向量数据库"。但最小实现就长这样： 

index = { "C01": 向量(年假),  "C02": 向量(出差住宿),  "C03": 向量(市内交通),  … }   # 一张 (块,向量) 表

def search(query, k=3):
    qv = embed(query)                                  # 问题也变向量
    对每一块算 cosine(qv, 该块向量)                    # 比相似度
    排序取前 k 名 → 返回那 k 块的【原文】               # 最近邻

生产向量库优化的是三件事：更快（亿条里检索不线性扫）、能持久（存磁盘/分布式）、更多功能（过滤、元数据）。 本课先用一张 Python 字典 + 8 个向量，把"原理"和"表"看透，比上来就背数据库 API 值得。

本课语料：虚构「云杉科技员工手册」（模型绝不可能背过）

为了让"检索才答得出"是决定性的，语料选一份模型从没见过的虚构公司内部手册，切成 8 个主题段落：

块主题 一段里藏着的事实（判定用）
C01年假满 1/3/5 年各 10/15/20 天，结转最多 5 天
C02出差住宿报销一线 600/晚，二线及以下 400/晚，48h 补票据
C03市内交通报销打车限 22 点后/恶劣天气
C04补充商业医疗险门诊报 80%、上限 5000、住院报 90%
C05开放 API 限流120 次/分，429，15 分钟为 P0
C06发布窗口周四 20–22 点；紧急修复须 CTO 书面批准 + 24h 复盘会

C08远程办公周三远程日、提前一天登记

为什么不全塞整本？——又贵，又会稀释注意力

有人会问：干脆把 8 块全发给模型不就行了？两个理由不这么做：

  • 贵：每道题都拖全文，等于把一本书每次重印一遍（第 6 课的账；本课镜 3 用 count_tokens 实测：全量 ≈ 591 token，只喂 top-3 ≈ 318）。
  • 稀释注意力：第 7 课引过 Anthropic 的实测——上下文越长，模型找回关键信息的能力越差（context rot / lost in the middle）。塞得越多，你要的那句越容易被淹没。

检索注入 = 只喂"相关那几页"，而不是整本书。这正是 Anthropic《上下文工程》里 read selective（只读相关） 这一条的落地。

RAG 跟第 7 课的窗口/摘要，各管哪一段？

容易混，分清楚就值回票价：

工具管的是对付的
第 7 课：窗口 / 摘要 对话历史（短期记忆：我们上几轮聊过什么） 输入太长、装不下、越聊越贵
本课：RAG / 检索注入 外部知识（长期记忆：公司政策/文档，模型没背过） 模型"不知道"却必须答对的内容
诚实提醒：RAG 的上限 = 检索那一环；检索断了，模型会"连引用一起编"

检索没把对的那页送进来，后面给多强的模型都白搭——本课镜 1/镜 2 会用翻车现场证明：模型没资料时不是老实说"不知道"，而是自信地编， 甚至假装引用了手册里根本不存在的条款。生产里你要做两件事兜底：① 提示词写明"只依据参考资料、资料里没有就说没有"（软）；② 用 eval 盯住它有没有在材料外编（硬，往后 M6 讲）。 还有个反直觉点：公司越小、资料越少（几万字以内），直接全文塞 + 提示词缓存 可能比上 RAG 更简单划算——Anthropic 官方都这么建议（见第 5 节必读）。RAG 不是越用越高级，是"资料大到塞不下/常更新"时才出手。

诚实提醒（教师实测，必读）

① 判定口径：每道题都标了"应命中的块"（ground truth），脚本打印的是检索 top-1 命没命中、关键词打分过没过下限——这些是确定性的； 模型的回答只是佐证，它的具体措辞会因换模型/换提示词而变（比如闭卷时它编的假流程每次版本不同，但"编不出 CTO/复盘"这件事是稳的）。 ② 关键词那一路加了个命中下限 0.15：真实检索器都用分数下限把"没把握的命中"滤掉，防拿噪音当答案——这是工程常规，不是本课专属。 ③ 你看到的 token 数会因 DeepSeek 对同一文本切词稳定而基本一致；模型回答的字数则影响 output，本课不比 output。

Introducing Contextual Retrieval — Anthropic（官方博客）
RAG 检索质量的官方工程范式：切块会丢上下文（一块孤立的"门诊报销 80%"不知道在说哪家、哪年）→ 给每块加一句"上下文前缀"再向量化，检索失败率可降近一半； 还强调 embedding 会漏精确串（如错误码 TS-999），所以要跟 BM25（字面/词频检索）双轨合流——本课镜 2 的"关键词(2-gram) 对照"正是 BM25/字面这一档的最小代表，你已亲眼看过它俩互补不互斥。

Text embeddings — OpenAI（官方文档）
"embedding = 把文字映射成向量、距离近 = 语义近"这一概念的出处。对照看：OpenAI 有 text-embedding-3-small/large（对话走 GPT、向量走 embed，同为"两家组装"）；DeepSeek/Anthropic 官方都不内置 embedding（Anthropic 官方推荐 Voyage 等伙伴模型）。本课本地 bge 小模型扮演的正是 text-embedding-3-small 的"角色"。

延伸对照：Anthropic 官方在 Contextual Retrieval 里也提醒——资料库很小（<20 万 token，约 500 页内）时，配提示词缓存直接全文塞可能更简单划算，别为上 RAG 而上 RAG。OpenAI 官方 blog 有《Introducing text and code embeddings》与 vector store 相关文档可互参。
