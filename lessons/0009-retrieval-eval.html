给 RAG 装一把尺子：检索评估
（eval 第一次上手 · Hit@k / MRR · 混合检索 · 阈值标定）

上一课你能让 RAG 答对几道题了，但"答对了几道、换了写法是不是更好、阈值该设多少"全凭感觉。 今天给你的 RAG 装一把尺子：手写一份评估集、算四个客观指标，然后用它把上一课亲手量出的两个悬案一一结清—— 阈值该设在哪（上一课那个 0.6 到底错在哪）和 追问要不要改写。再顺手量出：把关键词和语义合流，比任何单路强多少。

使命：3 个月转 AI 应用工程师 约 100–130 分钟 需要：第 8 课环境（本课不用再装任何东西） 花费：几分钱 token

面试官问过一个很多人答不好的问题："你说你的 RAG 做得不错——你怎么知道？" 答"我试了几个问题都答对了"是学生答案；答"我有 22 道标注过的题，Hit@3 从 0.95 调到 1.00，阈值按分数分布标定过"才是工程师答案。 差别不在技术难度——造这把尺子只要 20 行代码——而在有没有意识到它必须存在。 今天这一课，就是让你从此以后说"更好了"的时候，手里都是数字。

1 · 心智模型：没有尺子，就没有"改进"，只有"变化"

先承认一件事：上一课的成果，没有任何东西能证明它"好用"

上一课你跑通了最小 RAG，也亲眼看了几面镜子（闭卷会编、关键词换说法会断）。但那时候你手里能说的只有"我看它答对了"。 于是下面这三个问题，你一个都答不了：

  • 我今天动了检索的几行代码——它到底是变好了还是变坏了？还是只是"不一样了"？
  • 上一课那个 MIN_SCORE = 0.6，是对的吗？该往上还是往下？
  • 我把手册从 8 块扩到 300 块，会掉多少？值不值得补个 rerank？
本课一句话核心

评估（eval）= 一份自己标的评估集 + 几个客观指标。 有了它，"感觉变好了"被翻译成"Hit@1 从 0.73 涨到 0.91"，调参才从玄学变成工程。 没有尺子，你只能看到"变化"；有尺子，你才知道那是"改进"。

尺子怎么造：评估集 + 四个刻度

评估集就是你自己写的一批题，每道题标注一个 gold（这道题的答案应该命中哪一块）。 有了 gold，机器就能自己判对错了——不用人看、不用模型自评。四个通用刻度（任何 RAG 项目、任何向量库都通用）：

指标含义它回答什么问题
Hit@1 top-1 里有没有 gold 用户第一眼看到的对不对？（最严格）
Hit@k top-k 里有没有 gold 我要注入给模型的那几块里，答案在不在？（RAG 最该看这个）
Recall@k 该拿的 gold 拿全了几成 答案横跨好几块时（"出差交通+住宿+餐补分别多少"），是不是漏了几块？
MRR@k 第一个 gold 的名次取倒数（第 1 名 1.0 / 第 3 名 0.33 / 没进 top-k 记 0） 答案排得靠不靠前？——它比 Hit 更敏感，"答案从第 1 掉到第 3"这种退化只有它看得出来

Hit 和 Recall 会分家：如果一道题的答案横跨 3 块，而你只捞到 1 块，Hit@3 照样是满分（"中了"），Recall@3 只有 0.33（"该拿的没拿全"）。 这就是为什么两个都要看——只看 Hit，你会以为自己挺好，其实模型每次都在半块材料上作答。

题怎么出：一半的功夫在这里

  • 从语料反向出题：先想"这题该命中哪一块"，再写问句。写不出唯一 gold 的题，说明你的语料有歧义、或者这题该拆成两道——这本身就是有价值的发现。
  • 三种问法都要有：术语型（"429 是什么意思"——字面串是关键词的主场）、口语换说法型（"骑车摔伤去诊所缝针能报吗"——语义的主场）、追问型（"那另外那部分呢"——谁都不擅长，第 3 节专治）。三类混着出，尺子才量得出差别。
  • 用真人的话出题，别照抄语料原话。全照抄的话，关键词那一档会虚高到无敌——量出来的就是假的。
  • 题集是资产，要长：线上每被问住一次、每修一个检索 bug，就往里加一道题。这不是"测试"，这是你的回归测试集——改代码前跑一遍，才知道自己没把昨天修好的弄坏。
我出题时真踩的坑：gold 标错，三路"全错"

我写了一道题「凌晨一点收工打车回家，这笔钱能报吗？」，信心十足地标了 gold = 市内交通报销（C03）。 一跑：关键词、语义、混合三路全"错"——全都指向加班补贴那块。一查语料，加班补贴那块明写着"加班到 21:00 之后打车可报销"。 不是检索器坏了，是我的 gold 标错了。后来我把这道题改成了一句真正只属于 C03 的问法（台风天打车见客户）。 记住这条：指标异常时，先怀疑题，再怀疑检索器。评估集本身也需要评审。

有了尺子，四个旋钮才有名字

RAG 的检索环节，你能拧的就是这四颗旋钮。本课把它们全量一遍，并且每一颗都遵守同一条纪律：一次只动一颗，其余不动——这就是"调参"和"瞎试"的分界线。

  1. 检索器选型：关键词（字面）／语义（embedding）／混合（两路合流）
  2. 融合权重：混合时两路各占多少话语权
  3. 分数阈值：低于多少分就判定"没检索到"（上一课那个 0.6）
  4. top_k：一次往 prompt 里塞几块

旋钮② 的答案长什么样：两路合流，用 RRF 而不是加权分数

关键词和语义是互补的，这是上一课就看到的：语义兜住"换个说法"，关键词兜住精确串（错误码、缩写、"429"这种）。 问题是怎么把两路排名合成一个？最直觉的做法是"分数加权求和"，但上一课你已经亲手证明过这不成立： 关键词的重合率（没重合就是 0）和余弦（中文短句天然在 0.3~0.8）是两种量纲，直接相加要先归一化、调参，很脏。

工程上的标准答案是 RRF（Reciprocal Rank Fusion）：只看名次，不看分数。某块的融合得分 = 两路里各自名次倒数的加权和。 名次是无量纲的——"第 1 名"在哪一路都是第 1 名，量纲问题被顺手绕过去了。想让语义更有话语权，就给它更大的权重。 

score(块) = w_关键词 × 1/(60 + 它在关键词路的名次) + w_语义 × 1/(60 + 它在语义路的名次)
            ↑ 60 是业界默认的平滑常数；w = 权重，是要调的旋钮
诚实提醒：合流治的是"漏"，不是"排第一"

RRF 合并两路时会把某一路的错答案也一起顶上来——本课实测就抓到两例：语义明明排对了，混合反而把关键词的错答案顶到了第 1 名。 所以别指望"混合 = 全面更强"。它的真实价值在 Hit@k / Recall@k（"答案有没有被漏掉"）那一栏， 而不是 Hit@1。这也是为什么必须分开看指标——只看一个数，你会得出相反的结论。

旋钮③ 的答案：阈值不是拍脑袋，是把分布摊开看

上一课你给检索加了分数下限，当场就有人（你自己）问："0.6 这个数凭什么？"标准做法只有一条： 把正样本和负样本的分数分布都算出来，看它们分不分得开。

  • 正样本分数 = 这道题里答案块拿到的最高分（希望它高）
  • 负样本分数 = 这道题里非答案块拿到的最高分，也就是"噪音的天花板"（希望它低）

两条分布分得开（噪音最高 < 答案最低）→ 中间那段空隙里随便挑一个阈值都一样好。 两条分布重叠 → 落在重叠区里的阈值必然两头不讨好：卡高一点就误杀答案，卡低一点就放进噪音。 这时你要做的不是"再试试 0.55"，而是承认阈值救不了、去提升检索质量（合流、rerank、换 embed 模型）。 阈值是最后一道保险，不是主力。而且它不能跨路搬运、也不能跨语料抄——语料一变就得重标（本课实测会给你看这个数）。

旋钮④ 的答案：看曲线拐点，不看感觉

k 越大，答案块越不容易被切掉，但 token 线性涨、注意力被稀释。正确做法是把 k 从头扫一遍，画指标曲线 + token 曲线， 取"指标到顶、钱还没涨"的那个拐点。这是本课最容易上手的一次真实调参。

还有一件上一课留下的悬案：追问必须"自足"

多轮对话里，用户很少说完整的话——"那二线城市呢""那另外那部分呢"。这种查询不自足：脱离上文根本不知道自己指什么。 上一课你看到模型有时会自己把它改写成完整查询、有时不会，而这件事直接决定检索命中。本课用尺子量出它值多少， 并且确认一件事：查询改写（query rewriting）必须是你显式做出来的一步——要么在工具描述/system 里明确要求"query 要自足"， 要么专门加一个改写环节（本课的镜 3 就是一个 20 行的最小实现）。别赌它自己发生。

诚实提醒（读数字前必看，教师实测）

① 判定口径：每题都标了 gold，脚本算的是"答案块有没有进 top-k"——这些指标是确定性的、可复现的。 模型只在镜 3 的"改写"一处出场，且它的输出被原样打印出来给你检查。 ② 分辨率：22 道题上，名次差一名 = 4.5%。所以"0.91 和 0.95"之间只差一道题——这个量级的差距不足以下结论。 看指标时永远先问："这个差距比尺子的噪音大吗？" ③ 题是我出的、语料也是我写的，出得太顺手 → 指标偏乐观：真实语料的检索比你看到的难。 ④ 同一个评估集反复用来调参，调久了就会过拟合到这套题上。生产做法：评估集持续扩充（把线上真问题补进去）+ 留一批题不参与调参、只做验收。

挑战 A（必做，约 25 分钟）· 亲手给尺子加刻度，并发现"指标是被题集定义的"

打开 code/0009-eval-lab.py，你要改的都是文件顶部那两块数据。三步：

  1. 加 5 道你自己的题：照语料里的"易混对"出——年假（C01）／病假（C09）／调休（C10）是一组，出差住宿（C02）／出差餐补（C13）／出差交通（C14）是一组，数据分级（C22）／数据出境（C23）是一组。 每题写成员工会真正问出口的话（别照抄语料），标上 gold，加进 QUESTIONS，重跑。
    要观察：四路的指标各动了多少？你新加的题里有几道落在【各路分歧】那一节？
  2. 删一块语料再跑一遍：把 C12（加班餐补与夜间打车） 从 CHUNKS 里删掉，重跑镜 1 和镜 2。
    要观察：哪些题的 top-1 变了？镜 2 里"负样本最高分"（噪音天花板）有没有跟着变？——这一条最能解释"为什么阈值会随语料失效"。
  3. 加一路检索器：仿照 kw_scores 写一个"只看块标题（主题词）匹配"的打分函数（CHUNKS 每项第二个字段就是主题名），包成"返回全库排序的块号列表"（照 rank_of(...) 那样），再加进 RETRIEVERS，看它在 22 题上拿多少分。
    要观察：它是不是比完整的关键词路更差？为什么"标题就够用"这个直觉不成立？

口答（想清楚再说给我听）： ① 你加了 5 道题之后，如果四路指标都下降了——这能不能说明"检索器变差了"？为什么？ ② 为什么说"评估集决定你能看见什么"？举一个你加题后才发现的问题。

挑战 B（加分，约 25 分钟）· 用尺子回头调你 0001 里的 search_manual

上一课你在 code/0001-minimal-agent.py 里挂了一把 search_manual，还自己加了 MIN_SCORE = 0.6 和 top_k。 当时那两个数是拍出来的（你也很清楚）。现在你有尺子了，把它们量出来：

  1. 标定阈值：按镜 2 的办法，给 0001 的检索那一侧也算两条分布——正样本用 0009 的 22 题 gold；负样本除了"非答案块"，再补几道"手册里根本没有"的问题（比如"公司年会抽奖规则是什么""团建经费每人多少"，注意别用上一课已经用过的"下午茶"），把这几道的最高分也统计进来。看重叠区在哪，据此把 MIN_SCORE 定成一个你能说清理由的数。
  2. 顺手把语料换成 30 块：把 0009 的 CHUNKS 整表搬进 0001（前 8 块原文一致，所以搬到哪都不会答错）。重跑你上一课的自检问题（出差住宿 → 600）。要观察：块数从 8 变 30，同一道题的 top-1 分数变了没有？阈值还成立吗？
  3. 加一步查询改写（本课的核心增量）：在 0001 里加一个函数，在调用检索之前先把用户的问题补全成自足 query（把最近两轮的对话内容拼进 prompt 让 flash 改写；直接抄 0009 镜 3 的 SYS_REWRITE + rewrite_query）。 然后在 REPL 里实测这组追问：先问"员工补充商业医疗险住院能报多少？"→ 再追问"那门诊那部分呢？"
    自检：追问那一次，看它检索用的 query 是不是被补全了（把改写前后的 query 都打印出来），答案对不对。

交给我：你定下的 MIN_SCORE 和理由（哪两条分布、重叠区在哪、你为什么往这边偏）；以及改写那一步实测的"救回／弄丢"结果。

4 · 收束：确认你"真的会了"

自我解释练习（最重要的 3 分钟）

合上代码，用你自己的话讲给空气（或发给老师我）：
"评估 = ____（一份我标的题集） + ____（客观指标）。没有尺子，我只能看到____，看不到____。
四个刻度：Hit@1 问____；Hit@k 问____；Recall@k 问____；MRR 问____。
题集要从语料____出题，覆盖____／____／____三类问法；指标异常时先怀疑____。
混合检索用 RRF，因为它只吃____、不吃____，绕开了不同检索路的____问题；
它的收益主要体现在____那一栏，而不是 Hit@1，因为 RRF 会把某一路的____也顶上来。
阈值该设多少，要看____与____两条分布分不分得开；分不开时该做的是____，不是继续试数字。
追问之所以捞不到，是因为 query 不____；改写必须是____的一步，而且要用____验收。"
填不出来就翻回第 1 节再讲一遍——这正是把短期记忆变成长期记忆的机制。

本课产出

  • ✅ 能给任何 RAG 项目造一把尺子：评估集（题 + gold）+ Hit@1/Hit@k/Recall@k/MRR 四指标
  • ✅ 亲手量出四路检索器：关键词 0.73 ｜ 语义 0.91 ｜ 混合 0.91（Hit@3 1.00）｜ 混合·语义×2 0.95（Hit@1）
  • ✅ 说清"合流治漏不治排第一"，以及 RRF 为什么用名次绕开"量纲不可搬运"
  • ✅ 会用"正/负样本分布 + 重叠区"标定阈值，并解释上一课那个 0.6 错在哪（误杀 32%）
  • ✅ 量出 query 自足性的价值：把追问补全后，同一套检索器 Hit@1 从 2/5 → 5/5
  • ✅ 扫出 top_k 的拐点：k=3 之后指标全平、token 却涨到 8 倍

必读（Primary Source）

Demystifying evals for AI agents — Anthropic（官方博客，2026-01）★ 本课首选原典
目前最权威的 agent 评估一手文（副标题："让 agent 有用的那些能力，也正是让它们难以被评估的原因"）。它讲的正是本课往上一层的同一件事： 评估 = 给 AI 输入 + 用评分逻辑测输出；难点在从单轮 → 多轮 → agentic 的迁移（多轮工具调用、改状态，误差会累积放大）。 读它的时候请对照本课：**你今天量的只是"检索那一端"（Hit@k / Recall@k / MRR，确定性、可复现），它讲的还有"生成那一端"和"整条 pipeline 那一端"该怎么量。** 它附录里列了工业界的 eval 框架——你现在手写过前一半，看那张表就不再是黑盒。

Introducing Contextual Retrieval — Anthropic（官方博客，2024-09）
上一课你已经读过它"给块加上下文前缀"的部分。今天重读其中两点：① embedding 会漏掉精确串（错误码、缩写）→ 所以要跟 BM25（字面/词频检索）双轨合流——本课镜 1 的题 02（"RTO 是多少"语义连 top-3 都没进、关键词排第 2、混合排第 1）就是这条的现场证据；② 检索质量的提升要靠可量的方法而不是直觉，这正是本课在做的事。 顺手核对官方那几个数（本课备课已直抓原文核实）：单加上下文前缀把失败检索降低约 49%，再叠加 rerank 后约 67%。

第 7 课读全书、第 8 课读 read selective。本课补最后一层："怎么知道你的上下文策略是对的"——靠评估，不靠感觉。整个 M3 到此闭环：先会管（7）、会取（8）、现在会量（9）。

Ragas · 指标清单（开源框架，官方文档）
工业界最常用的 LLM/RAG 评估框架，把本课手写的那几个指标做成了开箱即用的成套指标。它按任务分组： RAG 组有 Context Precision / Context Recall / Faithfulness / Response Relevancy（注意官方现行名字是 Response Relevancy，不是老叫法 answer relevancy）；另有 Agents 组（Topic Adherence / Tool Call Accuracy / Agent Goal Accuracy）与 Natural Language Comparison（Factual Correctness / Semantic Similarity）、传统非 LLM 指标（BLEU / ROUGE / Exact Match）。 看这份清单时请对照本课：凡是带 context 的指标量的都是"检索那一端"（本课），带 faithfulness / response 的量的才是"生成那一端"——后者要另起一套评估（M6 的正题）。你现在能手写前一半，就不怕后一半的黑盒。

延伸：BEIR 检索基准（github.com/beir-cellar/beir，学术界怎么跨 15+ 数据集比较检索器——你会发现它们用的正是 Hit@k / nDCG 这一族指标。本机访问 GitHub 不稳定，打不开就先跳过）；OpenAI 官方 Evaluation best practices（按"不确定性来源"分层：输入层评指令遵循 / 输出层评功能正确性 / Agent 层评工具选择与参数抽取 / 多智能体层评 handoff 准确率——同一件事的 OpenAI 命名）。 工具会换代，指标不会。

⚠ 网络可达性（2026-09-10 备课实测）：以上 www.anthropic.com/engineering/* 与 docs.ragas.io 从本机可直连；而 Anthropic 的 API 文档站（platform.claude.com，旧别名 docs.claude.com）对大陆 IP 做地区封锁，OpenAI 的开发文档站对自动化抓取返回 403 反爬（浏览器正常打开即可）。所以本课把"一定读得到"的原典压在 Anthropic 工程博客上——这也是官方写得最实的一档。
