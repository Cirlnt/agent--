## 本课要回答的问题（承第 6 课钩子）

第 6 课收尾埋的钩子：对话到多长该"截断/摘要/归档"才划算？（M3 记忆与上下文的入口）。本课把它落成三个连续的问题：

1. **Agent 到底有没有记忆？** 有——它"记得"你当前塞在输入里的全部历史；没有——模型是无状态函数（第 6 课已立），跨请求什么都留不下。多轮能"对上话"，唯一原因是**你每轮把历史原样喂回去**。
2. **让一个只答一句的 Agent 变成真·多轮对话，代码要动什么？** 几乎不动 agentic loop，只加两层东西：一个**外层读输入的死循环** + 一个**把 assistant 的回答也 append 回 messages 的动作**（新手最常见的坑：只存 user、不存 assistant → 下一轮"断片"甚至 400）。
3. **对话无限长怎么办？** 三招上下文管理：**截断 / 滑动窗口 / 滚动摘要**。各自能压住什么、会丢掉什么、要额外付出什么（摘要本身也要花一次模型调用）。这就是第 6 课"第 4 把扳手：别让对话无限长"的实现课。

## 本课一句话核心（教学定调）

**Agent 没有记忆，只有"你每轮喂回去的历史"。** 它"记得"= 历史还在上下文窗口里；多轮不断链 = 你原样喂回；历史太长会越聊越贵（第 6 课）甚至撞上限 → 三招管理：**截断 / 滑动窗口 / 滚动摘要**。想要"记得更久又不多烧钱"，出路是**别把所有历史都喂进去，只喂相关的**——那是 RAG（下一课）。

## 心智模型（教给用户的分层）

- **记忆分两层看**：① 上下文窗口里的"现成记忆"（short-term / working memory）= 你发的 system+工具+历史；② "外部记忆"（长期）= 你自己存出去、需要时捞回来（文件/DB/向量/RAG），模型自己不碰它。
- **多轮状态不是模型的属性，是你代码的产物**：messages 列表 + "每次把 assistant 回答也追加回去" = 多轮状态；漏 append assistant、只 append user，对话当场断片（新手高频 bug）。
- **上下文窗口 = 稀缺预算**：它同时被【system + 工具说明书 + 历史】占着，每轮模型把整段重读（第 6 课）。窗口有限（撞了 400/quality 崩），无限长不可取 → 用三招压缩历史：
  | 招 | 做法 | 保住 | 丢掉 | 额外代价 |
  |---|---|---|---|---|
  | 截断(truncation) | 到长度直接砍掉最老 | 近况 | 最早 | 无（最省） |
  | 滑动窗口(window) | 只留最近 N 轮 | 近 N 轮 | N 轮之前的全部 | 无 |
  | 滚动摘要(summary) | 老的压成一段摘要、留最近原文 | 要义 | 细节数字 | **每次摘要重写花一次模型调用**；失真 |
- **三招都不是"记忆"，都是"取舍"**：想"记得更久 + 不无限烧钱 + 细节不丢"，靠窗口/摘要都不行——正确出路是**检索注入**（RAG）：把历史/知识存外部，每轮只喂最相关几段。本课只指路，下一课落地。

## 实验设计（code/0007-memory-context-lab.py）

领域沿用天气 agent（SUPPORTED 四城 + 当前时间），工具只留 get_weather / get_current_time，查完自然语言收尾（省掉 report_weather 那一路模型调用，降噪、降本、把镜头对准记忆）。**每轮只把【user 提问 + assistant 最终答复文本】存进 history**（对话记录层），agentic loop 的 tool 往返不入库——这正是"应用层的记忆 = 你选择记录什么"的示范。

- **镜 1 · 无状态 decisive**：先跑两问"查上海天气"→"那北京呢？"（能答 = 靠历史里的上海），再问"我第一次问的是哪个城市、天气多少？"。对照组：同样的 probe **冷启动**（不带任何历史）→ 模型没有信息来源，答不出/承认无记录。打印"此刻模型输入里含不含'上海'事实"的**确定性检查** + 模型实际回答，双轨取证（防幻觉干扰结论）。
- **镜 2 · 三策略同跑一场长对话**（约 6 问，同一脚本场景）：对 keep-all / window(最近 2 轮) / summary(老历史压成一句话摘要) 三策略跑同一对话，记忆测验用同样两道"最早事实"题（第一次问的哪个城市 / 巴黎几度）。每策略打印：策略 → 历史里事实还在不在(确定性 has_fact) → 模型答对没 → 总模型调用次数 → 总读取 token（input+cache_read 之和，工作量口径，与缓存折扣解耦）。decisive：**keep-all 全记得但 token 只涨不跌；window token 有上限但最早事实必丢；summary 有上限又保住要义，但多花一次摘要调用 + 细节数字可能失真**——tradeoff 三角。
- 收尾打印三策略对同一"最早事实"问题的答案并排，供课件引用。

- **挑战 B（加分）· 量 tradeoff**：把 lab 里窗口的 `KEEP_LAST_TURNS` 从 2 调到足够大，让"最早事实"测验也从 fail 变 pass，看总 token 涨了多少 → 亲自量出"记忆完整度是用 token 买来的"。口答：为什么滚动摘要比滑动窗口多花钱？它买到的是什么？

## 潜在误区（预判要盯）

- 以为"Agent 会自己记住"、以为断链/健忘是模型的问题 → 点破：断链 = 你少 append 了（几乎总是只 append user）；健忘 = 它本来就没见过那段（窗口裁了/没喂）。
- 把 assistant 回答漏存（尤其 end_turn 分支）→ 本课核心 bug，镜 1 / 挑战 A 都踩。
- 以为"摘要免费" → 摘要重写 = 一次模型调用（有自己的 cost），镜 2 用调用次数/总 token 量出来。
- 以为"窗口/摘要能无限压成本 + 不丢记忆" → 都有丢（窗口丢整段、摘要丢细节数字）；真"记得久又不贵"是检索注入（下一课 RAG），本课先立"记忆=取舍"的心智。
- 拿缓存当救兵（第 6 课教训）：缓存只把重复前缀打折；窗口/摘要砍的是"别老读那么长的历史"，两者不互斥、各管一段。

## 厂商对照 / 原典钩子
