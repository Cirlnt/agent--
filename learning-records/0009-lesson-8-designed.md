## 本课要回答的问题（承第 7 课钩子）

第 7 课收尾立的钩子：想"记得久 + 不无限烧 + 细节不丢"，窗口/摘要都做不到，出路是**把历史/知识存到外部、每轮只把最相关的几段检索进来喂**。本课把它落成三个连续的问题：

1. **模型没见过我们公司的政策，为什么能答对？** 不是它记得、不是它变聪明了——是你在提问前，把答案所在的段落**检索**出来、塞进了这次的 prompt（开卷考试：先把书翻到那一页再让你看，而不是让你背书）。RAG = 检索（retrieval）+ 增强生成（augmented generation）两个半场：真正答话的还是那个无状态函数（第 6/7 课立），RAG 改变的是"这次请求里多了几段精选原文"。
2. **"检索"凭什么知道哪段相关？** 字面/关键词不够：同事换一种说法你就搜不到。本课用 **embedding**：把每段文字和一个问句都变成一个数字向量，语义越接近、向量离得越近（余弦相似度）。把"语义"翻译成"几何"，检索就成了"在向量里找最近邻"。
3. **一套最小 RAG 有哪几块、向量库是什么？** 五步：**切块 → 每块算向量 → 建索引 → 提问时把问题也变向量、取最相似的 top-k 块 → 把这几块原文拼进 prompt 让模型作答**。向量库不神秘 = 一张（文本, 向量）的表 + 余弦排序；生产用的 Chroma / FAISS / pgvector 只是在做同一件事——更快、能持久、能上亿条。

## 本课一句话核心（教学定调）

**RAG = 先把你的资料切成块、每块算好向量；用户提问时把问题也变向量，挑出最接近的几块**原文**塞进 prompt，再让模型只依据这些原文作答。** 模型还是那个模型——你只是把"该看的几页"事先翻好喂给它，喂的是**最相关的原文**而不是整本书 → 既答得出模型没背过的私有知识，又不把全量塞进上下文（省 token、不稀释注意力）。这就是第 7 课那句"记得久 + 不烧钱 + 细节不丢"的工程答案，也是 Anthropic"上下文工程"里 **read selective（只读相关）** 的落地。

## 心智模型（教给用户的分层）

- **RAG 是"两段式"，别神化**：先检索（在资料库找几段原文）→ 再增强生成（原文+问题一起给模型）。真正答话的还是同一个对话模型；RAG 改的是"这次喂了什么"。面试第一句答这个 = 说明你懂它不玄。
- **长期记忆 = 你自己存出去 + 用时检索回来**（第 7 课第 2 层记忆的落地）：手册在模型记忆之外（模型从没背过），你要答它 = 先检索到相关段、当"参考材料"喂进去。
- **embedding 把语义变成几何**：一个 embed 模型把"文字"映射成向量；相似的文字→向量近。铁律：**向量只在自己这个 embed 模型里可比**（别拿两家 embed 模型的向量互算相似度，就像别拿公里数比斤两）。本地 bge 小模型 = ¥0、离线。
- **检索有几档**：字面/关键词 → 语义（embedding，本课）→ 重排 rerank（在 top-k 里再精排，延伸）。**RAG 质量的上限 = 检索质量**：检索没捞对，后面给多强的模型都白搭。
- **注入那一下是你早就会的拼 prompt**：生产常把检索结果放 system 或"参考材料"，并写明"只依据材料回答、材料里没有就直说不知道"——软性防编；硬防靠 eval + 你自己校验。
- **切块是检索的粒度**：整本书塞不进、塞进也稀释（context rot，第 7 课引过数据）→ 切成自洽的块、按块检索、只喂 top-k 原文。块太大颗粒粗、夹带噪音；太小断语境。本课用手工"主题段落"切，保持每块自洽。

## 实验设计（code/0008-rag-lab.py）

语料 = **虚构"云杉科技员工手册"**（模型绝不可能背过 → 检索才答得出的决定性来源），切 8 块主题自洽段落，每块含具体编号/数字/规则。本地 embed = `fastembed` 加载 `BAAI/bge-small-zh-v1.5`（512 维，ONNX CPU）。自建最小内存向量索引 = `[(chunk_id, text, vector)]` 列表 + 余弦 top-k（**不引向量数据库**，点破"向量库不神秘"）。问答用 flash。**检索成败用确定性判定**：ground-truth 每题标"应命中的 chunk_id"，打印 top-1 命没命中（has_chunk 检查），模型回答只当佐证（第 7 课诚实口径照搬）。

- **镜 1 · ★ 检索注入才答得出（闭卷会编）**：选一道**闭卷猜不中**的手册题——"紧急发版"：真值"须经 CTO 书面批准 + 发布后 24h 内补复盘会"只在 C06，是**公司特有流程**（试过"出差住宿 600"作闭卷题 → flash 凭常识猜中 600、削掉决定性，故换）。三种喂法：A 零注入（模型裸答）→ 编一套"合理但假"的公司流程（含『CTO』/『复盘』期望 False）；B 注入检索 top-1 那段原文 → 照手册答出 CTO 书面批准 + 复盘会（含『CTO』/『复盘』期望 True）；C 全量把 8 块都塞进去 → 也能答对但 prompt 大得多。三轨打印：注入的原文片段、模型答、确定性 has_fact（『CTO』『复盘』）、喂进去的 input token（count_tokens 口径，第 6 课）。decisive：**B 又准又小；A 会编（连引用都敢编）；C 又贵又多**——这就是检索注入存在的原因。
- **镜 2 · ★ 关键词检索 vs 语义（embedding）检索**：用【补充医疗险】**同一件事问两遍**做对照：题 A"照手册原话问"（员工补充商业医疗险的门诊费用报销比例是多少？）→ 关键词重合度 0.62 ≥ 命中下限 0.15、够用；题 B"换说法问"（周末骑车摔伤去诊所缝针…能按什么比例报销？措辞几乎不与 C04 字面重合但语义同指）→ 关键词顶到 C04 也只有 0.11 < 0.15 → 判无命中（检索=空），embedding 仍 0.67 稳稳捞对。打印：两题各自的两路 top-1 chunk_id + 打分 + 判定。再把题 B 的两路检索结果分别注入让模型答：关键词路检索=空 → 模型既答不出比例、还会**连手册里不存在的条款一起编**；语义路 → 照抄"门诊报销 80%"。decisive：**关键词 0.62→0.11 断了；语义 0.77→0.67 不断——embedding 靠"意思"兜住"换个说法"**。命中下限（此处 0.15）是真实检索器防噪音当答案的常规做法，讲课时点破。
- **镜 3 · 偷看内部 + 算一笔账**：打印 8 块 chunk 清单、某题的 top-3（chunk_id + 相似度条形 + 片段预览），把"索引就是一张表、top-k 就是排序"摊开；再量同一道题三种注入的 input token（注入 top-3 ≈ 小 / 全量 8 块 ≈ 大），把"为什么不全塞"用数字钉死。本地 embed 成本打印 ¥0（与第 6 课账单口径衔接）。

## 潜在误区（预判要盯）

- 以为"RAG = 把整本手册塞给模型 / 换了个更强的模型"→ 点破：模型没换、也没背手册；变的是这次输入里多了检索出来的几段原文。答错先查**检索**给对没有，别赖模型笨。
- 以为"向量库是神秘的高深组件"→ 最小实现就是 (文本,向量) 表 + 余弦 top-k；生产引擎优化的是速度/持久化/亿级规模。
- 以为"embedding 什么都能捞对"→ RAG 上限 = 检索上限：换说法要换在**同一语义邻域**；需要推理/反问/跨多块的题，纯检索救不了（这是往后 eval 与更高级检索的入口，诚实说）。
- 跨模型/跨 embed 模型向量互算相似度 → 禁止；同一个 embed 模型内才可比。
- 混淆"embedding 模型"与"对话模型"：embedding 输出的是**数字向量**不是文字；DeepSeek/Anthropic 官方现在都没有 embed 端点（Anthropic 官方推荐 Voyage 等伙伴模型），OpenAI 有 `text-embedding-3-*`——所以 RAG 天然是"对话 + 向量"两家组装的架构（本课 = DeepSeek 生成 + 本地 bge 向量）。
- 忘记告诉模型"只依据材料、没有就说不知道"→ 检索注入做完了，模型仍可能在材料不足时补编；提示词给边界（软），eval 盯（硬）。

## 厂商对照 / 原典钩子

- **embedding 这一环天生跨厂商**：DeepSeek 官方 API 无 embeddings（2026 实测，`api.deepseek.com/embeddings` 404），Anthropic 官方也无（Claude API 不提供向量化，官方最佳实践 = 用 Voyage / 自托管 bge 等伙伴），OpenAI 有 text-embedding-3-*。所以"对话 LLM + embedding 服务"本就是各家组装，不是某家的坑——本课用本地 bge 把"向量"做成 ¥0、离线、可复现。
- 概念对应（面试能用）：本课本地 bge-small-zh（512 维）≈ OpenAI text-embedding-3-small 的"角色"；Anthropic 侧无内置，等同类伙伴模型。向量检索的 top-k 概念跨所有向量库一致。
- 原典（必读，URL 交付前核实）：Anthropic《Effective context engineering for AI agents》的 **read selective**（第 7 课已读全书，本课落它"只读相关"的工程化）；Anthropic《Introducing Contextual Retrieval》（把检索放进上下文、块上下文增强的官方工程博客）；OpenAI Text embeddings 官方文档（embedding=语义向量这个概念的出处）。延伸：Building Effective Agents 里"检索增强工具"思想（挑战 A = 把 RAG 包成 agent 的一把工具，正落在它 workflow 与 agent 的接缝上）。
