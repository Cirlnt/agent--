# 第 4 课交付：话要放对抽屉（system prompt 与工具 description 的分工）+ 实测发现

2026-09-06。用户完成第 3 课后报到，按 lessons/0003 页脚预告与 NOTES 路线图（M2 · 提示词工程，含 system vs description 分工钩子），交付 **M2 第 4 课** `lessons/0004-prompt-engineering.html` 与实验脚本 `code/0004-prompt-engineering-lab.py`。主题承接第 3 课页脚预告 + KNOWLEDGE ⑤埋点（出口工具与真工具混在 TOOLS 时怎么防调错 → system vs description 分工）。

**本课核心心智（教学定调）**：把第 2 课"模型对工具的全部了解在 TOOLS"升级成全景——模型每轮读四样说明：**system / 对话历史 / tools(desc+schema) / tool_result**。system 是唯一"整台 Agent"层的抽屉，tools 每份说明书只属于单工具。**分工判据一句话：只管"一个工具"→ 该工具 description/schema；管"整台 Agent / 跨工具取舍 / 会话身份"→ system。** 反直觉核心（本课实锤）：**description 只对"这个工具该不该被调"负责，管不住"这台 Agent 该不该接这个活"——尤其当请求不需要任何工具（零工具纯知识域外）时，desc 层根本看不见它，只有 system 顶层边界能拦。**

**教师先跑验证（DeepSeek v4-flash / Anthropic 兼容端点，结论全部诚实化进课件）**：
1. **第一轮 A/B/C（守规矩对照，诚实记）**：小工具集（get_weather + get_current_time + report_weather 出口）+ 全域内问句，把同样分工分别放 ①不写 system ②写 system ③摊进各 tool description → **三镜行为完全一致、全部正确**（写诗域外直接 end_turn 不碰工具、查时间不乱套 report、混合天气+时间并行点单）。flash 太守规矩，这一层**看不出分工差异**——顺序纪律其实被"report schema 强制 condition 形如天气串 + 各 desc 自守够窄"物理锁了大半。→ 课件诚实口径定为：**分工价值不在"今天这模型放错就崩"，而在作用域正确 + 菜单变杂/换模型时站得住**（不是复刻第 2/3 课"防坏模型"）。这是第 4 课与第 2/3 课不同的教学层次。
2. **第二轮 P3（决定性）**：给菜单加一个**"万能"联网搜索工具** search_web + 问域外题，才逼出分工差异：
   - 镜 1 裸奔（无 system、search_web 万能）→ 币价去 `search_web({'query':'比特币价格 今日'})`、诺奖也去搜、珠峰凭知识照答 8848.86 → **无顶层定位 = Agent 自动扩张成"通用助手"（能力外泄）**。
   - 镜 2（同工具集 + system 声明"专用助手，只做天气/时间，域外直接拒"）→ 币价/诺奖/**珠峰全部礼貌拒绝**，工具集一字未变，边界由 system 立起。
   - 镜 3（无 system、把边界摊进各 tool description，search_web 收窄成"只搜企业内网"）→ **币价拒了（没有合法工具归宿，desc 自守起作用）但珠峰照答 8848.86** → **零工具的纯知识域外，desc 层看不见；"所有工具自守的加总 ≠ 整体边界"实锤**。
3. **珠峰对照（decisive 收尾）**：镜 2 拒 vs 镜 3 答、镜 1 答——同一句"珠穆朗玛峰有多高"，只差"边界写没写进 system"。这就是镜 2/镜 3 肉眼可分的一镜，已作为课件自测题②与动手 decode 的核心。
4. 顺带：镜 2 里 q_weather 会出现"先给一句 '我来帮你查询上海的当前天气' 再 get_weather"的圆场文本（同一 response 内含 text + tool_use），属正常、非本课主题。

**由实测定的教学口径（诚实化）**：本课不制造"裸奔必错"的叙事。对照组 A/B/C 全对直接写进课件 callout danger（"分工的价值不在今天崩不崩，而在作用域"），把 decisive 对比锚定在"菜单含万能工具 / 用户问域外零工具题"这一档（镜 1 vs 镜 2 vs 镜 3 的 q_btc / q_everest）。判断分工是否到位，不是"跑一次没错"，而是**能否说清每个抽屉的覆盖范围**（system 拦整台 Agent；desc 拦单工具；两者中间天然有"零工具请求"这道缝，只有 system 补）。

**ZPD 判断 / 对后续课的预测**：
- 挑战 A 的观察③（"加 system 前后，写诗这句子会不会被挡"）是动手层的 decisive 自检：用户若只看懂"我加了 system 所以规范"，而答不上"为什么第 3 课没 system 时它会写诗"，下课前要点破"默认通用助手 vs 声明专用助手"。
- 挑战 B（删 system 复现珠峰漏拦）检验对"desc 覆盖范围有洞"的理解，并故意把它跟第 2 课"白名单兜住域外、兜不住域内语义错"并置（都是"某层防线有盲区"）——能并置讲清 = 防线思维内化。
- 本课埋的 M2 后续钩子：system 该多长才够（太长的 system 稀释 desc？）；"要不要调工具"何时该交给独立 router 工具而非靠 system 写死（意图路由深水区）→ 留给流式 / 成本课之间的空档或专门一讲。
- 预测下一课主题：**流式输出（streaming）**（lessons/0004 页脚已预告）——thinking / max_tokens / 首 token 延迟都从第 3 课埋过线。
