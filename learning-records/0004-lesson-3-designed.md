# 第 3 课交付：让模型交出结构化数据（三种拿 JSON 的姿势）

2026-09-05。用户完成第 2 课后报到，按 lessons/0002 页脚预告与 NOTES 路线图（M2 结构化输出），交付 **M2 第 3 课** `lessons/0003-structured-output.html` 与实验脚本 `code/0003-structured-output-lab.py`。主题承接第 2 课页脚预告，并把第 2 课留的钩子（`additionalProperties:false`）焊进本课。

**本课核心心智（教学定调）**：程序要的是数据（dict），模型给的是文本；裸 prompt"只输出 JSON"是把"格式对不对"押在模型守规矩上，而**工具即输出**（定义一个输出工具、让模型用 tool_use 交答案、从 block.input 拿 dict）是把第 2 课的"靠契约不靠祈祷"原样搬到输出侧。**tool_use 本来就是免费的结构化输出**——这是与第 1/2 课心智的自然衔接。

**教师先跑验证（DeepSeek v4-flash / Anthropic 兼容端点，结论已全部诚实化进课件）**：
1. 裸 JSON：flash **相当守规矩**——干净句、甚至"target 里要带 ASCII 引号"（老板说"周六前务必回邮件"）它都自己转义好、直接 loads 成功。→ 镜 1 不再断言"一定脏"，口径改为：**"能跑，但不是你有锁"**；用"你顺嘴要一句人话确认"做触发镜（模型果然输出 `好的，已记下。\n{...}` → 直接 loads 崩 → 需手写剥除 = 打地鼠）。第 2 课"flash 守规矩"结论再次印证。
2. **实测新发现（重要）**：max_tokens 给小时（如 512），thinking 会**吃光输出预算**，模型可能一个字都不吐、`stop_reason=max_tokens`、返回空文本 → `json.loads("")` 崩。已作课件陷阱①；裸 JSON 在脚本里预算提到 4096 避免饿死。这条同时给"裸文本不稳定"补了一个非常真实的崩溃现场。
3. `tool_choice`：**指名强制 `{type:'tool',name}` 在本端点报 400**：*"Thinking mode does not support this tool_choice"*；`{type:'any'}` 可用且确实强制走工具（单输出工具时≈指名）。→ 课件把姿势③的"强制"诚实化为**厂商差异要实测、读报错、再定兜底**，小实验直接演示 400 原文。
4. `additionalProperties:false`：实测**不是物理拦截**；模型不硬加 schema 外键，而是把多余信息塞进自由文本字段（target 把"预算3000靠窗"全吞了）——第 2 课"域内最省力偷换"的输出侧变体。课件陷阱②口径：定位为合同"声明"，真拦靠自己代码验。
5. 挑战 A 可行性预跑：数据工具 get_weather → 回填 → 收尾出口工具 report_weather，flash 在该描述下**守规矩走工具收尾、不再给自然语言结语**（probe 两轮：get_weather→report_weather）。
