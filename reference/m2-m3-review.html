先讲清楚一件事：为什么不是"把九课重读一遍"

重读是复习里性价比最低的动作。因为读的时候你会产生一种"我都懂"的流畅感（fluency illusion），合上书却什么也调不出来——那是认得出，不是想得起。 真正把知识钉进长期记忆的是检索练习：先逼自己从脑子里往外掏（哪怕掏错了），再看答案。 所以今天的顺序是测 → 读 → 压：让泄漏出来的漏洞点名你该重读哪一篇、哪一节，而不是从头再刷一遍。

1 · 第 6 课：一轮轮聊下去，输入 token 实测是怎么涨的？（三个数）

445 → 553 → 667（token）。这就是「每轮重读全部历史」的账单形态：每轮都在变大，而且老历史被反复计费。

2 · 第 8 课镜 1：同一道手册题，三种喂法的 input token 各是多少？

零注入 132 ｜ 注入检索 top-1 原文 213 ｜ 全量塞 8 块 591。 记住那条比例：全量约是「只喂答案那一页」的 2.8 倍，答案却一样——多花的钱买的是零收益。

3 · 第 8 课镜 3：注入 top-3 大概要花多少 token？全量呢？（给量级即可）

注入 top-3 ≈ 318~336；全量 8 块 ≈ 576~596。也就是说「答案页 + 邻页」大概多加 150 token，再拖上全书再加 270 左右。

4 · 第 8 课镜 2：同一件事问两遍，关键词和语义各是什么表现？（四个数 + 那个下限）

关键词：照原话 0.619、换说法 0.107（命中下限 0.15 → 判「没检索到」）； 语义：0.770 → 0.665（几乎没动，照样捞对）。
一句话：关键词 0.62→0.11 断了，语义 0.77→0.67 不断。

5 · 第 9 课：四路检索器的 Hit@1 各是多少？（30 块语料 / 22 题）

关键词 0.73 ｜ 语义 0.91 ｜ 混合 RRF 0.91 ｜ 混合·语义×2 0.95。
配套记：混合在 Hit@k 与 Recall@k 上是 1.00 / 1.00（唯一的满分），而它的 Hit@1 并没有赢过语义——因为 RRF 会把某一路的错答案一起顶上来。

6 · 第 9 课：上一课那个 MIN_SCORE = 0.6，拿到 30 块语料上会怎样？（两个率）

误杀（正样本被滤掉）32%（7 道题）、漏放（噪音过线）14%。所以它两头不讨好——那个数是在 8 块语料上拍的，语料一变就失效。

7 · 第 9 课：余弦相似度的正/负样本重叠区大概在哪个区间？

约 [0.424, 0.647]（正样本最低 0.424，负样本最高 0.647）。落在重叠区里的任何阈值都必然两头不讨好——这才是「阈值只能取舍、救不了」的量化依据。
对照：关键词那一路的重叠区是 [0.062, 0.333]，量级完全不同 → 量纲不可跨路搬运。

8 · 第 9 课：追问「那另外那部分呢」这类查询，补全主题前后 Hit@1 各是多少？

原话 2/5 → flash 改写 5/5 → 人工自足版 5/5。同一套索引、同一路检索器，只把 query 补全就翻了倍——所以改写必须是显式的一步。

9 · 第 9 课：top_k 扫到多少就够？「全量塞」又是 k=3 的几倍 token？

Hit@k 到 k=2 就满了、Recall@k 到 k=3 也满了；之后 k=5/8/30 指标纹丝不动，token 一路从 197 涨到 1576——8.0 倍，买的是零收益。

10 · 第 9 课：语料和评估集的规模各是多少？（对比第 8 课）

语料 8 → 30 块（前 8 块原文未动，所以 0001 里挂的 search_manual 仍对得上）；评估集 22 题、每题标 gold（其中 2 题多 gold，用来让 Recall 和 Hit 分家）。

11 · 第 8 课：向量用的是哪个模型、多少维、花多少钱？

BAAI/bge-small-zh-v1.5，512 维，ONNX CPU 本地跑，¥0、离线可复现。
配套要能说清：DeepSeek 官方 API 没有 embeddings 端点（2026 实测 404），Anthropic 也不提供（官方推荐 Voyage 等伙伴模型），OpenAI 有 text-embedding-3-*。所以 RAG 天生是「对话模型 + 向量服务」两家组装。

12 · 第 1 课：Agent 比一次 API 调用多哪三样？（这句要能一字不差地说出来）

工具清单（tools）+ 可续历史（messages）+ 循环（agentic loop）。
Anthropic 的原话：an LLM using tools to perform a task in a loop。

课一句话核心（要能复述）必须记住的数 / 判据
1 M1
agentic loop		 Agent = 在循环里自主决定调工具的大模型；比一次调用只多工具清单 + 可续历史 + 循环。 stop_reason == tool_use 就转圈；end_turn 才收工。
2 工具说明书 模型对工具的了解只有 name / description / input_schema 三个字段，函数体它看不见。 雕说明书 > 换更聪明的模型；同一函数换三种说明书行为完全不同。
3 结构化输出 要 dict 别求它「只输出 JSON」，让它用 tool_use 交回来：block.input 天生是 dict，还有 schema 强约束。 裸 JSON = 软约束（打地鼠）；工具即输出 = 硬约束。
4 system vs desc 分工判据：管一个工具 → description；管整台 Agent → system。 不写 system 的 Agent 会悄悄扩权成「通用助手」，desc 自守拦不住。
5 流式 流式是 I/O / 体验层的开关，不是新的 agent 机制；用户体感 ≈ TTFT。 agentic loop 一行不改；工具参数半个半个到，工具那一拍省不掉。
6 成本与 token 烧钱 = 输出单价更贵 + 每轮重读全部历史（模型无状态）。 实测 445→553→667；max_tokens 是输出封顶不是省钱开关（thinking 共享预算）；缓存省「重复前缀的输入单价」。
7 多轮与上下文 它「记得」的边界 = 你此刻喂进窗口的内容；user 和 assistant 都要 append 回去。 三招都是拿细节换空间：截断 / 滑动窗口 / 滚动摘要；出路是外部存储 + 检索注入。
8 RAG 模型没换、没背书——变的是这次请求里多了几段检索出来的原文。五步：切块 → embed → 建索引 → 检索 top-k → 注入。 向量只在同一 embed 模型内可比；关键词换说法 0.62→0.11 断、语义 0.77→0.67 不断；检索=空 → 模型连引用一起编。
9 检索评估 没有尺子只有「变化」，没有「改进」；尺子 = 评估集（题 + gold）+ 指标。 Hit@1/Hit@k/Recall@k/MRR；四路 0.73/0.91/0.91/0.95；0.6 误杀 32%；重叠区 [0.424,0.647]；追问改写 2/5→5/5；k 拐点 3，全量 8 倍 token。
面试视角：这九课对应招聘方会问什么

「什么是 Agent？和普通调用有什么区别？」→ 第 1 课那句（工具清单 + 历史 + 循环）。
「模型输出不稳定/格式不对怎么办？」→ 第 2、3 课：工具即输出 + schema 强校验 + 兜底降级。
「怎么控制成本？」→ 第 6 课：拆 input/output 计价、缓存、max_tokens 封顶、别让历史无限涨。
「对话太长怎么办？」→ 第 7 课三招 + 「但真正的出路是检索注入」。
「你们怎么做 RAG？为什么不全塞？」→ 第 8 课五步 + 检索注入的经济账；主动补一句「资料很小的时候官方建议直接全塞 + 缓存」加分。
「你怎么知道你的 RAG 是好的？」→ 第 9 课：评估集 + 指标 + 阈值标定 + 自足性。这一问是这九课最值钱的一道，答得出的人不多。
